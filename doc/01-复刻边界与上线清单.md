# 01 · 复刻边界、调优记录与上线清单

配套文档：玩法配置与命令都在 [../README.md](../README.md)。这份只记录「为什么这样做」和「上线前要确认什么」。

## 1. 复刻的边界（版权与素材合规）

参照对象是 Count War 这一**玩法品类**（人群 + 数字门 + 箭塔 + 终点线），不是它的实现或素材。

| 维度 | 做法 | 结论 |
| --- | --- | --- |
| 玩法机制 | 复现「人数即血量、门做加减乘除、塔做远程消耗、终点结算」的规则结构 | 规则/机制不受版权保护，可复刻 |
| 角色形象 | 自建几何：合并的多部件体型 + 独立脸部贴图，配色为橙/青/品红阵营色 | 未使用原版蓝色士兵造型 |
| 贴图/背景 | 全部由图像生成工具产出，再经 `tools/posterize-assets.js` 后处理（裁水印、无缝化、瘦身） | 无外部素材引用 |
| 音效/配乐 | `tools/gen-audio.js` 用合成器（振荡器 + 包络 + 滤波）确定性生成 19 段 WAV | 未抓取、未采样原版音频 |
| 代码 | 本项目手写 Three.js，仅依赖 MIT 许可的 three.js r169，且已内联到 `vendor/` | 未反编译或复制原版前端代码 |
| 名称与标识 | 界面标题为通用词组 "Count War / 人数战争"，无原版 Logo、无原版站点标识 | 上线前建议按目标平台再做一次商标核查 |
| 网络请求 | 除可选广告脚本外，不请求任何第三方站点 | 满足单机要求 |

红线（不要改回去）：不要从原站点抓取任何 png/mp3/wasm/js；不要把 Poki/CrazyGames 的 SDK 常量写在 `index.html` 里（当前由 `src/ads.js` 按配置注入）；`game.config.json` 里不要提交真实广告密钥。

## 2. 手感与数值是怎么调出来的

按「先能跑 → 再公平 → 后好手感」的顺序，以下几处是实测后改动的，改动原因记在这里以免被回退。

1. **固定步长（1/60）驱动 `step()`**。最初直接把帧时长传给 `step()`，而集群物理内部还会把 `dt` 再夹一次以保分离稳定。结果是低帧率设备上：人群按被夹小的步长跑，箭塔/Boss/大门按整帧时长结算 → 同样的关卡在 17 fps 机器上必输、在 25 fps 上能过。现在 `Game.start()` 用累加器跑固定 1/60 步（每帧最多 5 步），人群和伤害时钟共享同一时间基；低于 12 fps 时整体放慢而不是让集群掉队。
2. **集群的加速上限**。大群被挤在路缘时，原先所有加速度预算都花在横向挤压上、不前进。现在锚点牵引与分离力分别限幅（`driveForce` 的 1.5×/3×），260 人以 6.4 前速仍能顶到终点。
3. **Boss 参战门控**。`resolveBoss` 只在蜂群真正贴到 Boss 前（`limit - crowd.cz <= 2.2`）才结算互相伤害，否则重置它的挥击计时。之前 Boss 在接触前就开始横扫，开局 1 秒就把刷新的 6 人清空。
4. **`creature-face.png` 的 3% 内缩裁剪**：脸部图集按象限切给不同阵营，裁边时留下 3% 内缩以避开生成图的角落水印又不撞象限边界；改动这个比例会让所有单位的脸错位。
5. **地面/天空无缝化**：`posterize-assets.js` 用「半幅平移 + 镜像延展」构造 512×512 地面与 1024×512 天空，任意重复次数不露缝；如果换成直接平铺，长跑道会看到明显接缝。

## 3. 自动化验收覆盖了什么

`node tools/smoke-test.js`（42 项，两轮：源码树 + `dist` 目录版 + 单文件版）。它是**真跑游戏**：只写 `input.laneX`，不直接改游戏状态；自动通关会自己挑存活人数最多的门、避不开的门就绕中立包。

分组：启动与菜单（含无语言按钮）→ 操控与结算（集群前进、拖拽转向、大门吃数、箭塔开火、HUD 与人数一致、标签绘制）→ 性能（Draw call < 60、软件渲染 fps > 12）→ 暂停/恢复 → 通关链路（打 Boss → 越过终点 → 自动进入下一关 → 峰值人数增长）→ 失败链路 → 中英文案与默认英文 → 域名锁（提示层、暂停玩法、3 秒后跳转、`?hostcheck=off`）→ 广告链路（插屏出现与关闭、激励复活发奖、控制台干净）→ 交付物（`dist` 目录、单文件能否脱离服务器直接双击运行）。

复跑注意事项：两轮别并行跑（软件渲染下会互相抢 CPU，fps 断言会假失败）；单文件版启动等待放宽到 60 秒。

## 4. 已知缺陷（可接受，未修）

- `assets/img/ui/logo.png` 的 alpha 通道不可信（生成图白底），界面标题走 CSS 文字，图片仅作装饰。
- 大门扣人飘字偶尔与门上的数字标签短暂重叠。
- 自动通关脚本在极低帧率下仍可能失败：人群被箭塔磨光后到 Boss 面前不足 40 人，此时按数值确实打不过（属平衡范围，不是 Bug）。
- 软件渲染（`--use-angle=swiftshader`，无 GPU）下 900 人级别会掉到 12 fps 附近；真机 GPU 稳定 60 fps、Draw call 25–33。

## 5. 上线清单

1. `game.config.json` → `hosting.allowedHosts` 填最终域名（含 `*.pipygames.com`），确认 `redirectUrl` 是 `https://pipygames.com/`、`redirectDelayMs: 3000`。
2. 拿到广告账号后：`ads.enabled: true`、`ads.provider: "google-adsense"`、`ads.testMode: false`、填 `google.clientId` 与需要的 `slots`；只填有权限的位，空 slot 会跳过。
3. `./build-web.sh`（或双击 `build-web.bat`）→ 上传 `dist/count-war-web/` 整个目录。
4. 上线后自查：换一台非授权域名验证 3 秒跳转、`?lang=zh` 中文文案、控制台无第三方报错、移动端横竖屏拖拽正常。
5. 需要单文件分发时给 `dist/count-war-single.html`，它内含全部素材，不依赖目录结构。
